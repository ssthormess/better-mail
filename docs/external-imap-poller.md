# External IMAP polling (F37)

The first poll of an account starts at UID 1 and fetches old mail oldest-first; it does not silently treat existing mail as imported. A UIDVALIDITY change resets the effective UID to 1 and replays the mailbox. `UID SEARCH UID N:*` can return UIDs lower than N (Dovecot does); those are filtered and the durable cursor is monotonic. A vanished UID between SEARCH and FETCH is ignored and later fetched UIDs continue progress. If FETCH reports a literal larger than 5 MiB, the client records/skips that requested UID and closes the session immediately without consuming the oversized body, so the next poll continues after it. Valid messages before the oversized UID have already been stored and later UIDs are picked up on the next tick. The cursor's bounded (128 entries) `skippedUids` list records those UIDs and `last_error` notes that skipped messages exist. UIDVALIDITY must be a canonical positive uint32, while lastUid can be zero; the uint32 ceiling completes without issuing an invalid N+1 query. Missing or invalid UIDVALIDITY fails the poll without advancing state.

Polling runs every minute in the self-hosted Node scheduler. A process-wide in-flight guard skips a new tick if the previous one is still running; the poll scans up to 1,000 due rows with NULL last-sync values first, skips in-flight/backoff rows without consuming its ten-account quota, processes accounts serially, and stops at a 50-second tick budget. A poll session has a 45-second absolute deadline, commands and TLS handshakes are capped at 12 seconds, stalled sockets are destroyed, socket reads are bounded to 32 MiB, metadata/search to 512 KiB/65,536 UIDs, and a batch to 50 messages/20 MiB with each message capped at 5 MiB. `last_synced_at` is checked inclusively at the one-minute cadence. Failed polls persist only fixed, sanitized messages and progressively back off from two minutes up to 30 minutes in process; after restart the counter resets, so failure backoff starts at one minute. Credentials are decrypted only for the active connection and are never logged or returned in persisted errors.

No IMAP dependency existed. `imapflow` was not added: a Node stream/socket client is not usable in workerd, while the required client must run with Node TLS semantics and certificate verification. This implementation uses a minimal RFC 3501 client over Node `net`/`tls`, with implicit TLS, STARTTLS, or plaintext as configured. TLS verification is always enabled; there is no skip-verify option. `tls_mode=none` sends the IMAP `LOGIN` command (username and password) and fetched mail in plaintext; it is intended only for trusted local networks. The client accepts `BODY[]` and `RFC822` literal response attributes and does not assume the UID precedes the literal; untagged responses such as `EXPUNGE` are skipped while waiting for the matching tagged completion.

This release deliberately supports self-hosted Node only. The poller imports Node sockets and Cloudflare workerd's `cloudflare:sockets` transport is a separate API, so the Worker scheduled handler does not invoke it. By default every resolved A/AAAA answer must be public/routable; resolution is repeated immediately before dialing and the chosen numeric IP is dialed, preventing DNS rebinding to a private address. Operators who intentionally fetch from LAN IMAP may set `EXTERNAL_FETCH_ALLOW_PRIVATE=1`; this is a host-wide trust decision because full-access mailbox delegates can configure external hosts. Do not set it on an install where mailbox managers are untrusted.

Fetched mail goes through `processInboundMessage` after raw bytes are stored. Its deterministic raw key hashes mailbox ID plus exact RFC822 bytes, and its `(mailboxId, rawR2Key)` lookup makes a replay after store-before-cursor failure idempotent. IMAP cursor writes are per-message and compare the expected cursor, enabled flag and updated timestamp, so stale pollers cannot overwrite a newer cursor or concurrent disable/edit; duplicate pollers may still perform network work, but only one can advance each fence. This assumes one self-hosted scheduler instance for fair cadence; use a single active poller per database. IMAP imports suppress historical side effects (auto-replies, notifications, webhooks, auto-drafts, DSN processing, and avatar lookup) while preserving parsing, spam scoring, folder rules, FTS indexing and threading.
