# External IMAP polling (F37)

The first poll starts at UID 1 and imports existing mail oldest-first. `UIDVALIDITY` must be a canonical positive uint32 and `UIDNEXT` must be a positive uint32; a missing/invalid value fails without advancing state. Search is bounded to `[startUid, min(startUid + 999, UIDNEXT - 1)]`, so even a 4,000-message inbox cannot exceed the IMAP response-line bound. At most 50 candidate UIDs are fetched per poll; if a window is fully scanned, the cursor advances through its empty UID gaps. Repeated polls continue with the next bounded window. The uint32 ceiling completes without issuing an invalid N+1 query.

Each candidate gets a `UID FETCH (UID RFC822.SIZE)` first. Only a closed, tokenized FETCH record whose UID and RFC822.SIZE match the request can authorize an oversized skip. A size above 5 MiB is recorded and advanced without fetching the body. The full body FETCH is then checked against the size result and exact UID/attribute; mismatches fail without advancing. Additional flags-only FETCH records are ignored. A tagged OK without the requested record triggers a targeted `UID SEARCH UID N:N`: confirmed absence is treated as an expunge, while a still-present UID is an unexpected response and fails the poll. Completed messages are stored and checkpointed one at a time, so a later failure does not discard earlier progress.

`sync_cursor.skippedUids` keeps the most recent 128 permanently oversized UIDs. The account API exposes that bounded list as `skippedUids`, never the raw cursor. `last_error` remains a warning while the list is non-empty; later successful polls do not clear it. The warning/diagnostics reset only when the upstream source is changed (which resets the cursor) or the remote UIDVALIDITY epoch changes. The cursor codec rejects incomplete IMAP objects, except the empty object retained as a legacy no-state value.

## Scheduling and claims

Polling runs every minute in the self-hosted Node scheduler. A local in-flight guard avoids overlapping ticks in one process. Candidate SQL filters active cross-process claims and the current process's retry-backoff IDs before applying the ten-account limit; NULL last-sync values sort first. The process-local failure map is pruned for removed/disabled accounts and resets on restart. Failed polls persist only fixed, sanitized errors and back off from two minutes up to 30 minutes.

Before any network or intake work, the poller atomically acquires a database lease on the account. The unique random claim token and expiry are stored in `poll_claim_token`/`poll_claim_until`, renewed while work is active, checked on every cursor write, and cleared only by the owning poller. Source identity (mailbox, protocol, host, port, TLS mode, username, encrypted password) is part of the fence. A source-setting PATCH clears the cursor; PATCH/DELETE are refused while a live claim is held. Claim fields are transient and omitted from backups. A crash releases the lease by expiry. Per-tick/account absolute deadlines are passed through the socket client and intake; callbacks are awaited rather than raced, so a timed-out operation is observed before releasing its claim. If intake finishes after its deadline, the cursor is not advanced and an idempotent retry can complete it.

The tick budget is 50 seconds; each account's IMAP session is capped at the earlier of the tick deadline and 45 seconds. Commands, DNS, and TLS handshakes are capped at 12 seconds. Socket reads are bounded to 32 MiB, metadata to 512 KiB, a search window to 1,000 UIDs (under the 16 KiB line cap), and each batch to 50 messages/20 MiB with each message capped at 5 MiB. Permitted DNS addresses are tried in resolver order under the same session deadline, dialing only their checked numeric addresses.

## Runtime, TLS, and egress

This poller supports self-hosted Node only. The Worker scheduled handler does not invoke it because workerd sockets use a different API. A minimal RFC 3501 client uses Node `net`/`tls`; implicit TLS and STARTTLS verify certificates and the original hostname. `tls_mode=none` sends LOGIN and mail in plaintext and is intended only for trusted local networks. Credentials with unsupported IMAP string characters are refused rather than serialized unsafely.

By default every resolved A/AAAA answer must be public/routable. Resolution is repeated before dialing, and the checked numeric IP is used for the connection, preventing DNS rebinding to a private address. Operators who intentionally fetch from LAN IMAP may set `EXTERNAL_FETCH_ALLOW_PRIVATE=1`; this host-wide trust decision permits full-access mailbox delegates to configure private destinations. Do not set it where mailbox managers are untrusted.

## Historical-import policy

All IMAP mail uses `intakeMode: "historical_import"`, including newly arriving messages. It still runs MIME parsing, routing/folder rules, spam classification, message storage, FTS indexing, and threading. It does **not** ingest DMARC aggregate reports, train/update spam reputation, register calendar invitations (and therefore creates no reminder), send auto-replies, notifications or webhooks, create auto-drafts, process DSN bounces, or look up avatars. DMARC-report mail addressed to the report endpoint is discarded after removing its temporary raw object. Normal SMTP/Worker queue intake keeps real-time behavior by omitting this mode.

Raw mail is passed through `processInboundMessage`. Its deterministic raw key hashes mailbox ID plus exact RFC822 bytes, and its `(mailboxId, rawR2Key)` lookup makes a replay after store-before-cursor failure idempotent.
